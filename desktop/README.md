# Windows ポータブル版

配布フォルダーをすべて展開して `katazuku.exe` を開きます。利用者側にNode.js・npm・ターミナルは不要です。
最初の画面の「まず架空データで体験する」から、設定や接続なしで8つの閲覧画面を開けます。
ウィンドウを閉じると初回設定へ戻れます。アプリを終了すると閲覧サーバーと子プロセスも終了します。

設定はElectronの `userData`（Windowsのアプリデータ領域）へ保存します。
配布フォルダーに個人データを保存せず、開発用の `KATAZUKU_*` 環境変数も引き継ぎません。
Google・ChatGPTの認証先もアプリの保存領域へ分離します。

対応範囲は初回ウィザード、設定の新規保存、ローカル診断、架空データ閲覧です。
Google本人認証・実データ同期・定期登録・自動更新・コード署名は未検証または未対応です。
コード署名がないため、正式公開前には配布と署名の手順を別途確認します。

## 開発者のビルド

Windows x64、Node.js 24とnpmを使います。リポジトリの公開ソースだけの作業場所で実行してください。

```powershell
npm --prefix desktop run package:windows -- C:\build\katazuku-windows-x64
```

初回ビルドは依存をダウンロードし、Electron、desktop専用のtsx実行環境、8画面のビルドを同梱します。
コアライブラリのランタイム依存は増やしません。出力先が既にあれば停止し、既存の配布物は削除しません。
開発中に同じlockfileで導入済みの依存を再利用する場合だけ、末尾に `--reuse-installed` を付けられます。画面は再ビルドします。配布確認は既定の完全ビルドで行ってください。

コピー対象はGit管理下の公開ソースの許可リスト、生成した架空スナップショット、各画面のHTMLとassetsだけです。
既存の `.env`、個人設定、ログ、DB、`snapshot.json` は読み取り・コピーしません。
生成した `manifest.json` に全配布ファイルのSHA-256を記録します。
Electron/Chromiumと各依存のライセンスもフォルダーと一緒に配布してください。

実機検証は `node desktop/tools/check-portable.mjs <配布フォルダー>` で行います。
検証では新しい一時プロファイルと架空の入力だけを使い、既存アプリのプロセスを操作しません。
初回画面の画像も保存する場合は `--screenshot` を付けます。非表示ウィンドウの画像取得が完了しない環境では、この追加確認はタイムアウトします。

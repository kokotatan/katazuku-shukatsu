# katazuku ロードマップ — 「本当に就活を楽にする」優先度

作成: 2026-07-08

## 思想(判断基準)
本人がやるのは **「判断」と「本番(面接・提出物の中身)」だけ**。
それ以外の散らかり(メール取得・整理・締切抽出・カレンダー登録・下書き・催促・進捗追跡)は
**システムが先に片付ける**。優先度は「どれだけ本人の手作業(toil)を消すか」で決める。

現状の一番の弱点: 多くの工程がまだ **Claude(対話セッション)を人が動かして** 実現している。
ゴールは、これが **無人で毎朝回る** こと。

---

## 優先度A(最優先): 「無人で毎朝回る」を完成させる
今日一日やった作業(メール確認・締切/URL登録・返信・受信整理)を、人が居なくても走る形にする。

- **A1. daily-sync / asa の無人稼働を確定させる** — 規模:小
  Gmail直結MCP(workspace-mcp)への乗り換えは完了。明朝の実走(タスクスケジューラ 8:23 / 9:00)で、
  未読取得→分類→締切抽出→カレンダー登録→受信整理まで本当に自動で回るかを確認・修正する。
- **A2. 締切・会議URL・面接予定の自動カレンダー化** — 規模:中
  「メール受信 → 締切/日時/会議URLを抽出 → career カレンダーに登録(面接=トマト/辞退=グレー)
  → URL紐付け → 前日+直前リマインダー」までを asa/daily-sync に組み込み、手動をなくす。
  今日はこれを1件ずつ手作業でやった。ここが自動化の本丸。
- **A3. サービスアカウント鍵の配置 → 選考管理シートの無人更新** — 規模:小〜中
  `status/service-account.json` 配置 + Sheets API + シート共有で、合否・進捗の自動反映を稼働させる
  (コードは完成済み。設定作業が中心)。

## 優先度B: 「本人の手作業」を消す
- **B1. 提出物の"中身"を書く = 本人がやる(自動化しない)** — 思想上の「本番」
  ES / SDS / 研究概要 の中身は本人の思考そのものなので自動生成しない。
  Claudeは素材出し(self-wiki / submit.local.md)・壁打ち・構成案までで支援し、書くのは本人。
- **B2. ブラウザ提出の代行** — ブラウザ操作MCP(Playwright)導入済み・動作確認済み(2026-07-08)
  Claude(headless / 次セッション)がブラウザを直接操作しフォーム入力まで代行できる。
  残: マイページ等ログイン要サイトは、Playwrightのプロファイルに初回ログインを保持させる設定(初回だけ本人がログイン)。
  submit-agent(`chrome-prompts/submit-agent.local.md`)の手順をブラウザMCPで実行する形に接続する。
- **B3. 送り忘れ検出の実戦化** — 規模:小
  「書いたのに送っていない下書き」を毎朝最優先で出す(asa 手順0に追加済み)。明朝の実走で検証。

## 横断方針: モデル非依存の土台(2026-07-10 Goal設定)

本人Goal「最高の就活環境を作る(ADHDでも最高の生産性を出す・もったいないことをしない)」。
AIモデルが変わっても(Fable→Opus等)改修・運用し続けられることを全作業の品質基準にする:

- **知見はチャットに残さずリポジトリへ焼き込む**。ブラウザ操作の技術知見は
  `chrome-prompts/08-browser-entry-knowhow.md`、運用手順は `scripts/daily-sync-prompt.md`、
  判断規約は `chrome-prompts/submit.local.md`。「賢いモデルなら気づける」前提の手順を残さない。
- **決定的な処理はプロンプトからコード(scripts/check-*.ts, mjs)へ降ろす**。LLM判断は
  分類・要約など本当に必要な箇所だけに絞る(regexで済むものはregexで)。
- **検証を自動化**: 新機能は check-*.ts を必ず添える。ビルド+全テスト通過をコミット条件のまま維持。

**A(無人化)→ B(手作業消し)→ C(どこでも化)→ D(第三波)**。
就活を一番楽にするのは A。まず「毎朝、結果を見るだけ」の状態を完成させる。

# Spec 09: katazuku Insight (AI示唆・未来志向) ※将来の機能拡張(未着手)

> 【位置づけ 2026-07-16】現行の insight アプリ(ナビ「今日やること / INSIGHT」)は、締切を機械的に
> 集計する **ToDo** であって示唆(insight)ではない。本specは、それとは別に「**AIが先を見て指示を出す**」
> 本来のInsightを新設する構想。バックエンド(認証+DB、2026-07-16に採用決定)が整った後に着手する。
> 現行アプリはToDoとして残し、本spec着手時にナビ英名を **INSIGHT → TODO** に改める。
> **本specは棚上げ(今は作らない)。土台と spec07/08 が揃ってから。**

## 目的

締切の一覧(=ToDo)ではなく、AI(`api/` 経由で Claude)が本人の就活データ全体を読み、
**「次に何をすべきか」「どこが危ういか」を未来志向で指示**する。毎朝 Claude が出している
「きょうやること(asa)」を、チャット/シートでなく **アプリ上の常設ビュー**として届ける。

## 前提(なぜ今まで無かったか)

アプリはルールベース・LLMは `api/` と Claude運用のみ、という方針(CLAUDE.md)。本specはその
**許可範囲である「api/ でLLMを呼ぶ」形**で実装するので方針に反しない。DBに就活データが集約されて
初めて横断推論できるため、backend+DB(認証付き)完成後に載せる。

## 入力(AIが読むデータ)

- 企業(選考段階・志望度・nextDate・停滞期間)/ 締切・要対応メール
- **面接ノート(spec08 の interview-notes)の「今後への示唆・懸念フラグ・ネクストアクション」**
- エントリー状況・自己PRの穴(profile)

## 出力(示唆)

- **次にやるべきこと**を優先度付き+理由つきで。例:「LayerXは二次から1週間停滞。放置は危険、日程確認を」
- **リスク警告**:「志望度Aなのに動けていない企業」「締切が近いのに未提出」「同じ懸念が複数社で再発」
- **前進の提案**:面接ノートの示唆を企業横断で束ねた"次の一手"

## 要件(構想)

1. `api/insight`(Vercel Function):**認証必須**。DBから上記入力を取り、Claudeに渡して構造化示唆(JSON)を返す。
2. ナビは「Insight」。現行の機械ToDoは「今日やること(TODO)」として併存させる。
3. **キャッシュ**:毎回LLMを叩かない。asa(毎朝)や更新時に生成→保存し、手動更新ボタンで再生成。
4. **コスト/頻度**:LLM呼び出しは1日数回程度に制限(asa連携)。

## デザイン

CLAUDE.md の SmartHR Design System準拠。示唆カードは優先度順、リスクは `red-*` を警告用途で使用。
各示唆に**根拠(どのデータ由来か)**を明示する。

## セキュリティ

就活データをLLMに送る処理は `api/`(認証の裏)で完結。プロンプト・結果はサーバ側で扱い公開しない。

## 受け入れ条件(着手時)

- `api/` のInsight生成の単体テスト(入力→期待する示唆項目)を追加。
- **backend+認証(DB)が前提。それ以前には着手しない**(棚上げ中)。

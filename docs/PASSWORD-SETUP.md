# 初回設定と閲覧認証

個人用・OSSで同じ初回設定、ログイン、再設定の方式を使う。公開ページへ最初に来た人に所有権を渡さず、書込権限を持つ所有者のPCだけが設定を開始する。

1. PC設定アプリが保存先を確認し、サーバー間通信で10分・1回限りの設定権限を発行する。
2. ブラウザーはURLのfragmentから設定権限を受け取り、直ちにURLから取り除く。所有者のPC名を表示し、本人が15文字以上のパスワードを2回入力する。
3. ブラウザーのWeb Cryptoで、保存先が生成した128bitのランダムsaltとPBKDF2-HMAC-SHA256（600,000回、256bit）を使って導出する。
4. 保存先は導出値にHMAC-SHA256をかけ、その結果とsaltだけを非公開R2へ保存する。HMACの秘密はR2の外のWorker Secretで管理する。用途識別子を含め、保存先の書込秘密を利用する。平文パスワードも導出値も保存しない。
5. 次回ログインでは同じsaltで導出して照合する。HMACの保存値そのものを送ってもログインできない。

導出値はパスワードと同等の秘密であり、HTTPSの本文以外で渡さない。URL、Web Storage、ログ、監視・解析サービスへ保存しない。この方式はTLSの代替やPAKEではない。アプリ自体やブラウザーが改ざんされれば入力を保護できないため、設定画面のCSPと配信物の検査も維持する。パスワード長の検査は通常画面で行い、APIは256bitの導出値だけを受け付ける。

計算量を下げると辞書攻撃への耐性が落ちるため、Cloudflare Workers FreeのCPU制限に合わせて反復回数を減らさない。重い導出は端末側で行い、保存先は一定時間の照合と試行制限を担当する。Cloudflareの有料プランへの変更は自動で行わない。

ブラウザーのセッションは30分、HttpOnly・Secure・SameSite=StrictのCookieを使う。OSSの別originにも対応する閲覧クライアントは、同一originのCookieを30分のBearerセッションへ引き換え、タブ内のsessionStorageにだけ保持する。正本の記録は保存しない。セッションはorigin、所有者の秘密、パスワードの設定世代に結び付ける。再設定は以前のセッションと未使用の設定権限を失効させる。書込秘密を変えた場合はパスワードの再設定が必要になる。

根拠: [OWASPのパスワード保存・HMACによるpepper](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Cloudflare WorkersのCPU制限](https://developers.cloudflare.com/workers/platform/limits/)。標準アルゴリズムの組み合わせであり、第三者のセキュリティ監査を受けたという意味ではない。

検査: `test:password-auth`で標準実装との導出一致、不正な方式、設定権限の同時消費、パスワードと導出値の非保存、保存値の再利用拒否、期限・origin・失効・旧キー拒否を確認する。Worker・閲覧クライアント・PC設定の検査はそれぞれ別に実行する。

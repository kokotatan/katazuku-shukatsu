# 自動録音の対象

会議URLのあるオンライン予定を自動録音の対象にする。面接・面談だけでなく、説明会・セミナー・イベント等も含める。種別が未分類でも、会議URLと以下の条件を満たせば対象にする。

- Google Meet、Zoom、Microsoft Teamsの既知の会議ホストに対するHTTPSリンクがある。
- 対面・来社・訪問などの指定がない。
- 開始時刻が明示され、終了が開始より後で、24時間未満である。終了が未入力の場合は従来どおり1時間として扱う。
- 中止・完了済み・録音しない指定の予定ではない。

インターン参加と宿泊は、会議URLが残っていても録音しない。日別・短時間でも同じ扱いとし、面談へ誤分類されていても除外する。インターン**選考の面接・面談や説明会・セミナー**は、上記の条件を満たせば対象にする。終日・24時間以上の予定も連続録音しない。

会議URLがあるために予定の種別を面談へ書き換える必要はない。`recordable=false` は録音しない指定として優先し、`recordable=true` でも宿泊等の除外条件は解除しない。未分類の支援予定の既定種別は `その他`、DBへの直接挿入時の録音可否の既定値はfalseとする。通常の支援予定の保存APIは会議URL等から録音可否を判定する。

短縮URLや不明なホストのURLだけでは自動録音しない。解決した会議URLを予定へ反映してから対象にする。会議サービスのトップページも会議リンクとして扱わない。

## 実装

`isAutomaticRecordingEligible()` が副作用なしで対象を判定する。カレンダー入力時の録音待機作成、支援面談の `recordable`、既存レコードの読み取り時にこの判定を使う。過去に保存されたtrueが残っていても、対象外の予定を許可しない。

録音ランナーも開始直前に同じ条件を再確認する。実行待機レコードがあることや、古い予定一覧が届いたことだけで録音を始めない。予定の登録・閲覧・空き時間の判定と、録音対象の判定は分ける。

個人用のWindowsランナーは予定一覧の生成時と受信後の両方で判定し、旧URLオープナーも同じ入口へ委譲する。OSSの中核APIも同じ規則と合成fixtureを持つ。OSSにWindows録音ランナー自体は含まれていないため、組み合わせるランナーはこのAPIを呼んでから録音を開始する。

## 検証

合成fixtureで通常の面接・面談、インターン選考の面接、日別インターン、宿泊、説明会、対面指定、URLなし、短縮URL、キャンセル、日時不正を確認する。インメモリDBで録音待機が対象外へ作られないこと、古いtrueが再判定されることも確認する。実データ・音声デバイス・第三者への通信はテストで使用しない。

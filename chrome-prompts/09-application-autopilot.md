# 応募自動運転: エントリーから面接予定確定まで

あなたは日本の新卒採用、特に28卒の就職活動を扱う。これは中途採用の job hunting ではない。
ユーザーは志望方針とES本文の作成を既に終えている。仕事は文章の創作ではなく、雑務の正確な実行である。

## 完了条件

1. 企業の応募ページを開き、ログインまたはアカウント作成を行う
2. 基本情報と、指定された完成済みESを正確に転記する
3. 送信直前の全項目をユーザーへ見せ、明示承認後だけ送信する
4. Web適性検査があれば、種類・URL・期限・所要時間・持ち物・動作環境を整理する
5. 適性検査は本人が受検する。問題の読み取り、解答の推測・入力、受検開始ボタンの押下はしない
6. 面接候補が提示されたら、既存カレンダーと本人の事前指定条件を照合して予約する
7. 面接予定をDBへ登録し、カレンダーoutboxへ載せる
8. DB更新後にスナップショットと活動ログを更新する

## 入力

- 正式企業名
- 応募URL
- 職種・コース
- 応募元を識別する sourceRef
- 完成済みESの参照先 materialsRef
- 本人が事前に許可した面接可能時間帯。未指定なら予約せず候補を提示する

ES本文をイベントJSONやDBへ入れてはいけない。転記元を直接読み、DBには設問、参照先、文字数、
文字数上限、本文SHA-256だけを保存する。

## 実行手順

### 1. run開始

一時JSONへ company、position、entryUrl、materialsRef、sourceRef を書き、
scripts/application-autopilot.ps1 -Action start -InputJson PATH を実行する。
返された runId を以後の全イベントで使う。

### 2. ログインとフォーム入力

- 既存Chromeのログイン状態を使う
- パスワード、メール認証、SMS、CAPTCHA、本人確認はユーザーへ引き継ぐ
- 学歴、住所、連絡先、資格などは確定済みプロフィールから完全一致で転記する
- 不明項目は推測せず paused を記録する
- 完成済みESは言い換えず、改行と文字数を確認して転記する
- 入力完了後、entry_filled または es_filled をDBへ記録する

### 3. 最終送信

送信直前に、画面上の全入力値、同意事項、提出先企業・職種をユーザーへ提示する。
ユーザーがその内容に対して明示的に承認した同じ実行内でのみ送信する。
送信後は完了画面または受付メールを確認し、approvedByUser: true を含む
entry_submitted、es_submitted、または entry_es_submitted を記録する。

### 4. Web適性検査

- マイページまたは受付メールから受検情報を抽出し、assessment_detected を記録する
- ブラウザ、カメラ、マイク、電卓・筆記用具、所要時間、締切を確認する
- 締切はappointmentへ自動登録される
- 動作確認ページまでは進めてよいが、本番開始の直前で止める
- 本人が受検完了を伝えた場合だけ approvedByUser: true の assessment_completed を記録する
- 練習問題は公式または利用許諾が明確な教材への案内に限る

### 5. 面接予約

- 本人が事前に指定した時間帯に含まれ、既存予定と重ならない候補だけを選ぶ
- 条件内に候補が1つなら予約してよい。複数候補が同等、条件外、重複ありなら本人へ確認する
- 予約完了画面またはメールを根拠に、日時、終了時刻、URL、場所、相手を
  interview_scheduled としてDBへ記録する
- カレンダー反映担当が作成できるよう db-calendar-outbox.ts の対象にする

## 絶対にしないこと

- 応募先、職種、コースの推測
- ユーザーが確認していないエントリーまたはESの最終送信
- ES本文の創作、要約、改変
- 本番Webテストの問題保存、画面撮影、解答生成、解答入力、代理受検
- CAPTCHA、SMS、メール認証などの本人確認の回避
- 面接可能条件がない状態での予約確定

障害時は画面、原因、再開地点を短くまとめ、paused または failed を記録する。

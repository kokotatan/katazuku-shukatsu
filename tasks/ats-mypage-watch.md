# ATSマイページ巡回見張り(spec13拡張)

## 背景・目的

メールで通知してこないATS(採用管理システム: HRMOS / i-web / axol 等)のマイページ内メッセージが
現在の見張り網(Gmail)の外にあり、取りこぼし源になっている(例: 「マイページのメッセージ2通を確認」が
nextActionに残り続ける)。毎日ログイン基盤(scripts/local-login: 資格ブローカー+隔離Chromeプロファイル、
spec13)を拡張し、主要マイページの新着メッセージを検知してDBへ反映する。

## 要件

1. 対象ポータルは `scripts/local-login/portals.json` に追記する形で増やす。第1弾は
   DBの company.mypage_url から頻度の高いATSドメイン上位3つ(axol.jp / i-webs.jp / HRMOS)を選ぶ
2. ログインは既存ブローカー(broker.mjs)を使う。エージェント・ランナーはパスワードを見ない(spec13の境界を維持)
3. ログイン後、メッセージ一覧ページの「新着・未読」を検出し、件名・日付・企業名を
   sync/mail-import-loop.json 互換の形式で出力 → db-apply-mail.ts で正本DBへ反映(冪等キー: ポータル+メッセージID)
4. 本文の取得はテキストのみ。添付やファイルはダウンロードしない
5. 新着があれば daily-sync のサマリと同じ経路で報告し、活動ログに1行残す
6. 失敗(MFA/CAPTCHA/欄検出不能)は spec13 と同じく入力せず停止し、理由を記録する
   (欄検出のヒューリスティック拡張は spec13「残作業1」を参照)
7. 実行はまず週2回(火・金の朝)から始め、安定したら毎日へ

## 完了条件

- 第1弾ポータル1つ以上で、実マイページの新着メッセージがDBの Inbox に現れる
- 回帰テスト(check-*形式)でメッセージ抽出とDB反映の冪等性を検証
- docs/INFRA.md の定常タスク表・spec13 の更新

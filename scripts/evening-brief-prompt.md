明日の面接・面談に向けた「前夜ブリーフ」を作成し、自分宛メールで届けてください。

手順:

0. `scripts/meeting-preparation-prompt.md` を読み、未完了の事前調査と準備を先に実施する。
   明日の予定が0件でも、将来の準備対象があればここで補う。前夜ブリーフの送信済み判定で準備を省略しない。
   調査不能なら理由を台帳へ残す。未完了を正常完了に偽装せず、通知できる既存の予定情報は届ける。

1. `cd sync` で `npx tsx scripts/brief-data.ts` を実行する(引数なし=明日JST)。JSONが出力される。
   `count` が 0 なら何もせず、最後に完了行だけ出力して終了する(メール・プッシュ・活動ログすべて不要)。
2. 重複防止: Gmailで `in:sent subject:(前夜ブリーフ) newer_than:1d` を検索し、明日の日付のブリーフを
   既に送信済みなら再送せず、完了行を出して終了する。
2.5 **メール突合(必須。DBだけを信じない)**: 予定ごとに、その企業からのメールを Gmail で検索し
   (例 `from:(会社ドメイン) OR subject:(会社名) newer_than:30d`)、**DBに無い情報を必ず拾う**:
   会議URL(変更・新規発行)・入室方法・録画の有無・準備物・服装・**当日までに提出が要るアンケート/書類の締切**・
   担当者名。拾った情報はブリーフに載せ、あわせて `sync/sheet-import-loop.json` へ appointments として
   書き出し `npx tsx scripts/db-apply.ts` でDBへ取り込む(次回以降はDBから出る)。
   インターン予定で交通費支給が明記されていれば`kind:"インターン"`とし、`reimbursementStatus`
   (全額=`full`、一部=`partial`、定額=`fixed`、本人精算なしの企業手配=`arranged`、支給なし=`none`)を入れる。
   領収書・利用明細等の提出が明記されている場合だけ`receiptRequired:true`にする。推測では設定しない。
   **2026-07-31の反省**: Sansanの確定メール(2次面接のMeet URL・録画告知・健康アンケート締切8/12)が
   DB未取込だったため、DBだけを見たブリーフから丸ごと落ちた。メール本文にしかない情報は必ず存在する前提で確認する。
3. 予定ごとに以下を1つのメールにまとめる(件名: `【前夜ブリーフ】M/D(曜) 予定N件`。曜日はJSTで検算):
   - **予定**: 時刻・種別・会社・ポジション・会議URL(そのままクリックできる形で)・場所
   - **相手**: linkedPeople / companyPeople から。名前・役職・過去に会った経緯と人物メモ(なければ「初対面・情報なし」と明記)
   - **前回まで**: pastInterviews の要点と、宿題・「次回までに」系の約束事(transcript_path のファイルを Read して
     質問リスト・宿題を拾う。ファイルがなければ recentEvents と selection_memo から)
   - **選考状況**: selection_status / next_action / 直近イベント
   - **想定問答**: 過去の面接記録と選考段階から、聞かれそうな質問3〜5個と答えの骨子、逆質問案2〜3個。
     `preparation`のdossierと準備済み資料を使い、根拠のない企業情報を創作しない。
     未完了なら手順0で補う。実際に調査できなかった場合だけ理由と再試行対象を明記し、本人へ調査作業を丸投げしない。
   - **準備物**: 案内メール由来の情報があれば(PC・イヤホン等)。データに無ければ一般的な準備のみ

   全予定の後、メールの最後に次の固定セクションを毎回そのまま載せる(本人指定の文言 2026-07-29。省略・言い換えをしない):

   ```
   ■ 話し方の心構え(毎回意識する)
   ・愛嬌
   ・笑顔
   ・ハキハキ
   ・分かりやすく
   ・クリティカルに話す

   ■ 面接で話す核
   ・ガクチカの学び: 問いの設定が一番価値がある
     (マッチングプラットフォームから、非エンジニアでも自動化環境を作り上げられる制御ソフトウェアへのピボット)
   ・就活の軸:
     市場 — 市場規模/人類の発展に寄与するドメイン/開かれる市場
     風土 — テック/人の良さ/エンジニア・デザイナー/ことに向かう
     経営陣 — タイミング/新しい世界を見せてくれるか
   ```
4. メールは mcp__google-workspace__send_gmail_message で okuyama.kotaro.career@gmail.com 宛に送る。
   本文はプレーンテキストで、見出し+箇条書きの読みやすい形にする。
5. プッシュ通知: `node scripts/push-send.mjs --title "前夜ブリーフ" --body "明日の予定N件のブリーフをメールに送りました" --url /prep/`
   を実行する(ロック画面に出るため企業名・人名は載せない)。失敗しても続行する。
6. 活動ログに1行残す:
   `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/log-activity.ps1 -By evening-brief -Action "前夜ブリーフ送付" -Why "明日の面接・面談に前回の記憶と相手情報を揃えて臨むため" -How "<予定件数と会社数>" -Link "Gmail" -Result "成功"`
7. **サマリの最終行に、他の文字を付けず単独で半角ASCIIで `=== evening-brief DONE ===` と必ず出力する**
   (全工程を実行できたとき、または手順1・2の条件で正常に何もしなかったときのみ)。

注意: ブリーフの事実は brief-data.ts、面接記録、出典付きdossier・面談準備資料に基づける。
会社の事業内容・面接官の経歴などを推測で書かない(想定問答の「質問」側は推測でよいが、
「事実」欄に創作を混ぜない)。

# katazuku evening-brief — 前夜ブリーフ(明日の面接・面談の準備)

明日({{BRIEF_DATE}})の面接・面談・説明会・テストに向けた「前夜ブリーフ」を作ります。
絵文字は使いません。曜日はタイムゾーン {{TIMEZONE}} で機械的に検算します。

## 入力

次のJSONは正本DBから集めた明日の予定です(`scripts/brief-data.ts` の出力)。予定・相手・前回の記録・直近の出来事が入っています。

```json
{{BRIEF_DATA}}
```

## 手順

1. 予定が0件なら何もせず、完了行だけ出力して終わる。
2. **メール突合(DBだけを信じない)**: 予定ごとに、その企業からのメールを google-workspace MCP で検索する
   (例: 件名に会社名を含む `newer_than:30d`)。DBに無い情報 — 会議URLの変更・入室方法・録画の有無・準備物・服装・
   当日までに提出が要るアンケートや書類の締切・担当者名 — を拾ってブリーフに載せる。
   拾った予定情報は `logs/brief-import.local.json` に `[{name, stage, position, appointments:[...], ref}]` の形で書き、
   `npx tsx src/db-apply.ts logs/brief-import.local.json` で正本へ取り込む(次回以降はDBから出るように)。
3. 予定ごとに次をまとめる(件名: `【前夜ブリーフ】M/D(曜) 予定N件`):
   - **予定**: 時刻・種別・会社・ポジション・会議URL(そのままクリックできる形)・場所
   - **相手**: linkedPeople / companyPeople から名前・役職・過去の経緯とメモ(無ければ「初対面・情報なし」と明記)
   - **前回まで**: pastInterviews の要点と「次回までに」系の約束事
   - **選考状況**: selection_status / next_action / 直近の出来事
   - **想定問答**: 聞かれそうな質問3〜5個と答えの骨子、逆質問案2〜3個
   - **準備物**: 案内メール由来の情報(PC・イヤホンなど)。無ければ一般的な準備だけ
{{REMINDER_SECTION}}
4. 事実は入力JSONと、実際に読んだメール・公式情報だけに基づける。会社の事業内容や面接官の経歴を推測で書かない
   (想定問答の「質問」側は推測でよいが、「事実」欄に創作を混ぜない)。
